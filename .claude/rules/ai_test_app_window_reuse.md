# 앱 창 다시 쓰기 (시험, 재현)

## 1. 규칙

- MUST: 앱을 띄워 확인하는 일은 **한 번 띄운 창을 이어서 쓴다.** 확인 하나마다 창을 닫았다 다시 띄우지 않는다.
- MUST: 창을 새로 띄우는 것은 아래 2장의 경우뿐이다. 새로 띄울 때는 그 이유가 2장의 몇 번인지 작업 보고에 적는다.
- 이유: 창을 띄우는 데 매번 10 ~ 15초가 들고, 시험 DB 접속과 모델 불러오기를 처음부터 다시 한다. 2026-10-22 작업에서 시나리오마다 창을 다시 띄워 기다리는 시간이 길어졌다(사용자 지적).

## 2. 새로 띄워야 하는 경우

| No. | 경우 | 이유 |
|---|---|---|
| 1 | 코드를 고쳐 다시 빌드했다 | 띄워 둔 창은 옛 빌드다 |
| 2 | 앱을 켤 때의 동작을 본다 | 마지막 화면 되살리기, 설정 읽기, MCP 서버 시작, 시험 모드 분기는 켤 때만 돈다 |
| 3 | 앱 설정 폴더가 비어 있어야 하는 시험이다 | 앞 시험의 설정, 저장한 접속, 비밀번호가 결과를 바꾼다 |
| 4 | 시험 모드 시나리오(`ERD_AUTO`)를 돌린다 | 시나리오는 「켜기, 한 번 돌리기, 결과 출력, 종료」 로 만들어져 있다 |
| 5 | 창이 멈췄거나 화면 프로세스가 죽었다 | 이어 쓸 수 없다 |

- 4번을 여러 개 돌려야 하면, 먼저 같은 확인을 띄워 둔 창에서 할 수 있는지 본다. 결과를 예전 빌드와 비교하는 회귀 확인처럼 시나리오 출력이 꼭 필요할 때만 시나리오로 돌린다.

## 3. 이어 쓰는 방법

1. 원격 디버깅을 켜고 한 번 띄운다. 시험용 설정 폴더(`ERD_USER_DATA`)를 따로 준다.
   ```bash
   ERD_USER_DATA="{시험용 폴더}" npx electron . --remote-debugging-port=9333 \
     --disable-features=CalculateNativeWinOcclusion --disable-renderer-backgrounding --disable-backgrounding-occluded-windows
   ```
   - 열 모델은 시험용 설정 폴더의 `session.json`(마지막 화면)에 미리 적어 두면 켜자마자 그 탭들이 열린다.
2. 화면 조작과 값 읽기는 agent-browser 로 같은 창에 붙어서 한다: `agent-browser --session erd --cdp 9333 ...`.
3. AI 도구는 설정 폴더의 `mcp-erd.json` 에 적힌 주소와 토큰으로 `tools/call` 을 보낸다.
4. 다음 확인 전에는 창을 닫지 않고 화면에서 원래대로 돌린다. 예: AI 변경은 「취소」, ERD 수정은 「되돌리기」, 열어 본 탭은 닫기.

## 4. 창이 화면을 그리지 않을 때

- 증상: `document.visibilityState` 가 `hidden` 이고, 화면 캡처와 `requestAnimationFrame` 이 멈춘다. 클릭이 먹지 않는다.
- 원인 1: 다른 창에 가려졌다. 1번 명령의 `--disable-...` 옵션 세 개로 막는다.
- 원인 2: 창이 최소화됐다. 옵션으로는 안 풀린다. Windows `ShowWindow(창, 9)` 로 되살린다.
- 원인을 확인하지 않고 창을 다시 띄우지 않는다. 다시 띄워도 같은 이유로 또 멈춘다.
