# 작업 문서 정리 (task 폴더)

숨은 전제: `task/` 폴더는 `.gitignore` 에 들어 있어 git 에 올라가지 않는다. 작업 문서는 할 일을 적어 두는 곳이고, 한 일의 기록은 git 커밋 내역이 맡는다.

## 1. 규칙

| No. | 강도 | 작업 상태 | 문서 처리 |
|---|---|---|---|
| 1 | MUST | 문서에 적힌 작업을 모두 마쳤다 | 문서 파일을 지운다 |
| 2 | MUST | 일부만 마쳤다 | 파일은 남기고, 문서 안에서 마친 작업 내용만 지운다 |
| 3 | NEVER | 어느 경우든 | 마친 작업을 문서에 「완료」 표시나 체크로 남겨 두지 않는다 |

- 「마쳤다」 는 코드 변경이 커밋까지 된 상태를 말한다. 커밋 전이면 문서를 그대로 둔다.
- 일부만 마쳤을 때는 남은 작업이 그 문서만 읽고 이해되게 「이유」, 「목표」 도 남은 작업에 맞게 고친다.
- 이유: 한 일은 git 커밋 내역에 이미 남아 있다. 마친 내용이 문서에 남아 있으면 다음에 문서를 읽을 때 무엇이 남은 일인지 가려내야 한다(사용자 지정 2026-10-23).

## 2. 예

```markdown
<!-- 작업 전: 대상 3곳 -->
| No. | 대상 | 위치 |
|---|---|---|
| 1 | stripParens | postgres.ts:56 |
| 2 | stripParens | mysql.ts:101 |
| 3 | stripParens | mssql.ts:98 |

<!-- ✅ 1, 2번만 커밋했을 때: 남은 3번만 둔다 -->
| No. | 대상 | 위치 |
|---|---|---|
| 1 | stripParens | mssql.ts:98 |

<!-- ❌ 마친 줄을 표시만 해서 남겨 둔다 -->
| 1 | stripParens | postgres.ts:56 (완료) |
```
