# ERD Tool 설치 안내

> 숨은 전제: Windows 10, 11 x64 PC 다. 설치 파일만으로 실행되며 Node.js, Java 같은 개발 도구는 필요 없다. DB 접속 정보는 BE 레포의 설정 파일에서 읽거나(3장 표 기준을 따르는 프로젝트) 「직접 입력」 으로 넣는다.

## 1. 준비물

| No. | 항목 | 꼭 필요한가 | 설명 |
|---|---|---|---|
| 1 | 설치 파일 `ERD-Tool-Setup-{버전}.exe` | 필요 | 관리자에게 받는다 |
| 2 | 접속할 DB 계정 | 필요 | 가능하면 읽기 전용 권한 계정을 받는다 (5장) |
| 3 | BE 레포 폴더 | BE 폴더로 접속할 때만 | 3장의 위치에 접속 설정 파일이 있는 폴더. 구조가 다르면 「직접 입력」 을 쓴다 |
| 4 | 마스터키 환경변수 `JASYPT_ENCRYPTOR_PASSWORD` | 설정 파일 비밀번호가 `ENC(...)` 일 때만 | 6장 |
| 5 | PowerShell 7 | 없어도 됨 | 내장 터미널 기본 셸. 없으면 Windows 에 들어 있는 PowerShell 5.1 을 쓴다 |
| 6 | Git for Windows (Git Bash) | 없어도 됨 | 내장 터미널에서 Git Bash 를 고를 때만 |
| 7 | Claude Code 또는 Codex | 없어도 됨 | 내장 터미널의 「AI 연결」 을 쓸 때만 |

## 2. 설치

1. `ERD-Tool-Setup-{버전}.exe` 를 실행한다.
2. 「Windows의 PC 보호」 파란 창이 뜨면 「추가 정보」 → 「실행」 을 누른다. 설치 파일에 코드 서명이 없어서 뜨는 창이다.
3. 설치 범위(나만 또는 모든 사용자)와 설치 폴더를 고른다. 기본은 나만, `%LOCALAPPDATA%\Programs\ERD Tool` 이다.
4. 설치가 끝나면 바탕화면과 시작 메뉴에 「ERD Tool」 이 생긴다.

- 설치한 버전은 설치 파일 이름과 「설정 → 앱 → 설치된 앱」 의 「ERD Tool」 항목에서 확인한다. 새 버전은 관리자가 나눠 준다(자동 업데이트 없음).

## 3. DB 접속 정하기

왼쪽 접속 패널에서 두 방법 중 하나를 고른다.

| No. | 방법 | 이럴 때 쓴다 |
|---|---|---|
| 1 | BE 폴더에서 | BE 레포가 아래 「BE 폴더 기준」 을 따른다 |
| 2 | 직접 입력 | BE 레포가 없거나 구조가 다르다. DB 종류, 호스트, 포트, DB, 계정, 스키마를 넣는다 |

BE 폴더 기준 (모두 맞아야 「BE 폴더에서」 가 동작한다)

| No. | 항목 | 도구가 찾는 것 |
|---|---|---|
| 1 | 설정 파일 위치 | `src/main/resources`, `src/main/resources/prop`, `src/main/resources` 중 처음 찾은 한 곳 |
| 2 | 설정 파일 이름 | `application-{프로필}.properties`, `.yml`, `.yaml` (같은 프로필이면 properties 가 이긴다) |
| 3 | 접속 키 | `db.url`, `db.username`, `db.password`. 없으면 Spring 표준 `spring.datasource.url`, `.username`, `.password` |
| 4 | URL 형식 | `jdbc:postgresql`, `jdbc:sqlserver`, `jdbc:mysql`, `jdbc:mariadb`, `jdbc:oracle:thin` |

- 위와 다르면 BE 폴더를 골라도 접속 목록이 비거나 일부만 나온다. 그때는 「직접 입력」 을 쓴다.

## 4. 쓰기 허용 프로필

BE 폴더의 프로필은 이름이 쓰기 허용 목록에 있을 때만 쓰기로 열린다. 나머지는 모두 읽기 전용이다(운영 이름이 `prod` 가 아닌 프로젝트도 막기 위해서다).

| No. | 이 목록이 정하는 것 | 내용 |
|---|---|---|
| 1 | 쓰기, 읽기 전용 | 목록에 없는 프로필은 DB 가 쓰기를 거부한다 |
| 2 | 기본으로 고르는 접속 | 접속 패널, SQL 탭, DB 비교 왼쪽의 처음 선택 |
| 3 | DB 비교 「DB 에 적용」 | 목록에 든 프로필만 바로 적용할 수 있다. 직접 입력 접속은 적용 전에 한 번 묻는다 |

- 기본 목록은 `dev`, `local` 이다. 개발 DB 프로필 이름이 다르면(`develop` 등) 도구를 끄고 `%APPDATA%\erd-tool\settings.json` 에 `"writableProfiles": ["develop"]` 을 넣은 뒤 다시 켠다.
- 공용 DB(시험 서버, 운영)는 도구에서 바로 바꾸지 않는다. 「DB 비교」 에서 Flyway 파일을 만들어 그 파일로 반영한다.

## 5. DB 계정 권한 (권고)

도구는 운영 DB 와 AI 조회를 읽기 전용으로 열지만, 이것은 도구 안의 장치다. 가장 확실한 보호는 DB 쪽에서 막는 것이다.

- 운영, 다른 팀 DB 에는 SELECT 권한만 있는 계정을 받아 접속한다.
- 특히 SQL Server, Oracle 에서 AI 조회를 쓸 때 권한을 줄인 계정을 쓴다. 도구는 AI 조회를 SELECT, WITH 한 문장으로 제한하지만, SELECT 안에서 부른 DB 함수가 데이터를 바꾸는 경우까지 막는다고 확인하지는 않았다.

## 6. 마스터키 (설정 파일의 비밀번호가 `ENC(...)` 일 때)

1. 시작 메뉴에서 「계정의 환경 변수 편집」 을 연다.
2. 「사용자 변수」 에서 「새로 만들기」 → 이름 `JASYPT_ENCRYPTOR_PASSWORD`, 값은 받은 마스터키.
3. ERD Tool 이 켜져 있었다면 끄고 다시 켠다.

- 마스터키 값은 문서, 메신저, 메일에 적지 않는다. 관리자에게 직접 받아 내 PC 에만 넣는다. 도구는 키를 화면이나 파일에 남기지 않는다.
- 자동으로 푸는 방식은 하나뿐이다: BE 레포 `src/main/java` 아래의 `EncryptorConfig.java` 에 알고리즘 `PBEWithMD5AndDES` 와 고정 salt 가 적힌 경우.
- 그 밖의 방식(AES 등)이거나 마스터키가 없으면 접속할 때 비밀번호 창이 뜬다. 「이 PC 에 저장」 을 고르면 Windows 계정 암호화로 저장해 다음부터 묻지 않는다.

## 7. 처음 실행

| No. | 할 일 | 화면 |
|---|---|---|
| 1 | 접속 고르기 | 3장대로 「BE 폴더에서」 또는 「직접 입력」 |
| 2 | 접속 시험 | 목록에서 골라 「접속 시험」. 읽기 전용 프로필은 표시가 붙는다 |
| 3 | 모델 폴더 정하기 | 모델(`.erd` 파일)을 둘 폴더. BE 폴더를 고르면 `{BE 폴더}/docs/erd/model` 이 기본으로 들어가니, 다른 곳을 쓰면 바꾼다 |
| 4 | 그룹 규칙 (선택) | 「DB 에서 불러오기」 위의 「그룹 규칙」 에서 규칙 파일을 고르거나 테이블 이름 접두어(예: `mst_, whs_`)를 넣는다 (8장) |
| 5 | ERD 열기 | 「DB 에서 불러오기」, 또는 「ERD 폴더 열기」 로 저장해 둔 모델 폴더 |

- 껐다 켜면 마지막 화면(ERD 탭, 저장 안 한 변경, SQL 탭 글자와 접속)이 그대로 열린다.

## 8. 그룹 규칙

그룹은 테이블을 이름 접두어로 나눈 묶음이다. 그룹 탭, 그룹 격자 정렬, 그룹별 MD 문서가 이것을 쓴다.

| No. | 방법 | 설명 |
|---|---|---|
| 1 | 규칙 파일 | `erd-groups.json` 형식 파일을 고른다 |
| 2 | 접두어 목록 | 쉼표로 넣는다. `mst_` 는 그룹 `mst` 가 되고, 어디에도 안 맞는 테이블은 그룹 `etc` 로 간다 |
| 3 | 모델 폴더의 `erd-groups.json` | 위 두 가지를 정하지 않았을 때 찾는다 |
| 4 | 그룹 하나 | 아무것도 없을 때 |

규칙 파일 형식

```json
{ "grp_rules": [{ "prefix": "mst_", "grp": "mst" }, { "prefix": "whs_", "grp": "whs" }], "grp_default": "sys" }
```

- 그룹 규칙은 모델을 처음 만들 때만 쓴다. 이미 있는 모델은 그 모델의 그룹을 그대로 쓴다.

## 9. MD 문서 양식 바꾸기

「내보내기」 탭의 「MD 템플릿」 에서 템플릿 폴더를 고르면, 그 폴더에 있는 같은 이름의 파일로 문서를 만든다. 없는 파일은 내장 템플릿을 쓴다.

| No. | 파일 이름 | 만드는 문서 |
|---|---|---|
| 1 | `group-tables.md` | 그룹별 테이블 정의서 |
| 2 | `tables-overview.md` | 테이블 목록 색인 |
| 3 | `menu-tables.md` | 메뉴 물리 테이블 목록 조각 |
| 4 | `db-compare.md` | DB 비교 결과 |

- 내장 템플릿은 설치 폴더 안에 있어 직접 고칠 수 없다. 레포의 `src/shared/export/templates/` 에 있는 같은 이름 파일을 복사해 고치면 된다.
- 문법은 두 가지다. `{{이름}}` 은 값 넣기, `{{#이름}} ... {{/이름}}` 은 반복이나 조건. 템플릿에 없는 값 이름을 쓰면 「`group-tables.md` 12째 줄: 템플릿 값 ... 이(가) 없습니다」 처럼 어느 파일 몇째 줄인지 알려 준다.
- 「메뉴 물리 테이블 목록」 은 메뉴마다 설계 문서(`{메뉴코드}-03-data-model.md`)를 두는 팀을 위한 기능이다. 그 체계를 쓰지 않으면 쓰지 않아도 된다.

## 10. 설정이 저장되는 곳

| No. | 내용 | 위치 |
|---|---|---|
| 1 | 화면 설정, 접속 목록, 쿼리 이력, 마지막 화면(`session.json`) | `%APPDATA%\erd-tool` |
| 2 | 앱 설정(`settings.json`: BE 폴더, 쓰기 허용 프로필, 그룹 규칙, 템플릿 폴더) | 같은 폴더 |
| 3 | 저장한 DB 비밀번호 | 같은 폴더, Windows 계정 암호화(다른 PC, 다른 계정에서는 풀리지 않는다) |
| 4 | ERD 모델 | 「ERD 저장」 때 고른 폴더 |

- 프로그램을 지워도 이 폴더는 남는다. 깨끗이 지우려면 제거한 뒤 `%APPDATA%\erd-tool` 을 지운다.

## 11. 제거

「설정 → 앱 → 설치된 앱」 에서 「ERD Tool」 → 제거. 또는 설치 폴더의 `Uninstall ERD Tool.exe`.

## 12. 문제 해결

| No. | 증상 | 확인할 것 |
|---|---|---|
| 1 | BE 폴더를 골랐는데 접속 목록이 비었다 | 3장 「BE 폴더 기준」 과 맞는지. 다르면 「직접 입력」 |
| 2 | 개발 DB 가 읽기 전용으로 열린다 | 프로필 이름이 쓰기 허용 목록에 있는지 (4장) |
| 3 | 접속할 때마다 비밀번호를 묻는다 | 마스터키 환경변수 이름이 정확한지, 넣은 뒤 도구를 다시 켰는지, Jasypt 방식이 6장과 같은지 |
| 4 | 「다른 DB 종류의 모델 폴더」 오류 | PostgreSQL 모델 폴더에 SQL Server 등 다른 DB 를 불러오려 한 것. 다른 폴더를 고른다 |
| 5 | MD 만들기에서 「템플릿 값 ... 이(가) 없습니다」 | 오류에 나온 템플릿 파일의 그 줄. 값 이름을 내장 템플릿과 비교한다 |
| 6 | 내장 터미널이 PowerShell 5.1 로 뜬다 | PowerShell 7 이 설치되어 있지 않은 것. 그대로 써도 된다 |
| 7 | 「AI 연결」 이 동작하지 않는다 | 내장 터미널에서 `claude --version` 또는 `codex --version` 이 나오는지 |

## 13. 예: 이 도구를 처음 만든 프로젝트의 구성

설정을 어떻게 맞추는지 보여 주는 한 예다. 이 구성이 아니어도 위 장의 기준만 맞으면 된다.

| No. | 항목 | 그 프로젝트의 값 |
|---|---|---|
| 1 | 설정 파일 | `src/main/resources/application-{dev, test, prod}.properties` (단수 `resource`) |
| 2 | 접속 키 | `db.url`, `db.username`, `db.password`, 비밀번호는 `ENC(...)` |
| 3 | Jasypt | `EncryptorConfig.java` 에 `PBEWithMD5AndDES`, 고정 salt |
| 4 | 쓰기 허용 프로필 | 기본값 그대로(`dev` 만 쓰기, `test`, `prod` 는 읽기 전용) |
| 5 | 모델 폴더 | BE 레포의 `docs/erd/model` (git 으로 관리) |
| 6 | Flyway 폴더 | `src/main/resource/db/migration` |
| 7 | 그룹 규칙, 템플릿 | 팀 문서 레포의 `erd-groups.json` 과 팀 문서 형식 템플릿 폴더를 골라 둔다 |

## 14. 관리자: 설치 파일 다시 만들기

| No. | 할 일 | 명령 |
|---|---|---|
| 1 | 의존성 설치 | `npm ci` |
| 2 | 시험 | `npm test`. DB 시험은 `test/.env.example` 을 `test/.env.local` 로 복사해 BE 폴더를 넣어야 돌고, 없으면 건너뛴다 |
| 3 | 설치 파일 빌드 | `npm run dist` → `dist/ERD-Tool-Setup-{버전}.exe` |

- 버전은 `package.json` 의 `version` 이다. 올린 뒤 빌드한다.
- 설치용 빌드(`npm run build`, `npm run dist`)에는 시험 모드(`ERD_AUTO`) 코드가 들어가지 않는다. 시험 모드 시나리오는 `npm run build:auto` 로 빌드한 뒤 돌린다.
- 빌드 설정은 `electron-builder.yml` 이다. 디버거 연결과 Node 로 실행하기를 막는 Electron 퓨즈, 한국어, 영어 화면 글자 묶음만 넣기, 내장 터미널 파일을 압축 밖에 두기가 여기 있다.
- 코드 서명 인증서가 생기면 `win.signtoolOptions` 에 넣는다. 지금은 서명이 없어 설치할 때 2장 2번 창이 뜬다.
